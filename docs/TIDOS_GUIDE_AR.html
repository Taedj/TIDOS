1الفكرة في سطرين

النموذج القوي يعلّم، وTIDOS يحفظ، والنموذج الضعيف يُقاد. عندما تعمل مع نموذج قوي، يراقب TIDOS كيف حُلّت المهمة: ما الملفات التي قُرئت أولًا، وما الفحوص التي شُغّلت، وأين حدثت الأخطاء، وما الذي صحّحته أنت. ثم يحوّل ذلك إلى «خطط عمل» خاصة بكل مشروع. وعندما تعمل لاحقًا مع نموذج مجاني أضعف، يعطيه TIDOS خلاصة قصيرة ومركّزة من هذه الخبرة، ويفرض عليه قواعد عمل صارمة (اقرأ قبل أن تعدّل، تحقّق قبل أن تقول «انتهيت»).

TIDOS لا يدرّب النماذج ولا يغيّر أوزانها. الهدف هو تطوير TIDOS نفسه: معرفته وقواعده وأدواته تكبر مع كل جلسة، وأي نموذج يعمل داخله يستفيد منها.

ما الذي يميّزه؟

  • يفرض القواعد بالكود (خطافات وأدوات)، لا بالنصوص الطويلة فقط.
  • يتعلّم من أدلة: فحوص نجحت أو فشلت، وتصحيحاتك؛ لا من كلام النموذج عن نفسه.
  • كل معرفتك الخاصة تبقى على جهازك في ~/.tidos.

من أين يتعلّم؟

  • من كل مشاريعك، وليس من مشروع TIDOS فقط.
  • عمل النماذج القوية له الوزن الأكبر.
  • لكنه لا يعدّل إلا نفسه: لا يلمس مشاريعك، يقرأ آثار العمل فقط.

3وضعا العمل: تعلّم وتوجيه

عندما تكتب START TIDOS في أي أداة (Claude Code أو OpenCode أو Gemini CLI…)، يكتشف TIDOS الأداة والنموذج المستخدم، ثم يحدد فئة النموذج من القواعد في config/models.json (ويمكنك تجاوزها في ~/.tidos/models.json). أي نموذج غير معروف يُعامَل كـ«ضعيف» من باب الحذر.

LEARN وضع التعلّم: نموذج قوي

  • النموذج يعمل بمستواه الطبيعي، دون قيود إضافية.
  • TIDOS يسجّل الجلسة: الأدوات، الملفات، الفحوص، تصحيحاتك.
  • يُطلب من النموذج تشغيل الفحوص الحقيقية قبل إعلان الانتهاء، وترك نصيحة قصيرة للنماذج الأضعف بعد كل مهمة مهمّة.

GUIDE وضع التوجيه: نموذج متوسط أو ضعيف

  • يستلم النموذج موجزًا قصيرًا (أقل من 4KB) بدل نصوص طويلة لا يتبعها.
  • يحصل على توجيه خاص بكل طلب: نوع المهمة، الخطوة الأولى، كيف حُلّت مهام مشابهة في هذا المشروع، والفخاخ المعروفة.
  • الخطافات تمنعه من التعديل قبل القراءة، ومن الإنهاء دون تحقق، وتوقفه بعد 3 أخطاء متطابقة وتقترح نموذجًا أقوى.

4الدماغ: أين تُحفظ المعرفة

كل ما يتعلّمه TIDOS يُحفظ خارج المستودع في مجلد خاص على جهازك، فلا يمسحه التحديث ولا يصل إلى GitHub:

المسارالمحتوى
~/.tidos/brain.dbقاعدة بيانات SQLite: الجلسات، المهام، استدعاءات الأدوات، الفحوص، التقييمات، أحداث XP، الأحداث المباشرة.
~/.tidos/playbooks/خطط العمل: لكل مشروع ونوع مهمة، كيف حُلّت، وأين يقع الكود، وما الفحوص التي نجحت.
~/.tidos/memory/ذاكرتك الخاصة، ومنها القواعد التي كرّرتها (LEARNED_PREFERENCES).
~/.tidos/drafts/مسودات مهارات ووكلاء متخصصين وقضايا: لا تُفعَّل إلا عندما تنقلها أنت.
~/.tidos/proposals.jsonlطابور التطوّر: اقتراحات لتحسين TIDOS نفسه.
~/.tidos/reports/تقارير المهمة اليومية.
~/.tidos/backups/نسخ احتياطية من الدماغ.
~/.tidos/control.jsonمفاتيح الإيقاف (تُعدَّل من مركز التحكم).
~/.tidos/bin/الأدوات التي ثبّتها TIDOS بالتنزيل المُتحقَّق منه.
كل نص يدخل الدماغ يمرّ أولًا عبر جدار الخصوصية: المفاتيح وكلمات المرور والبريد والمسارات الشخصية تُحذف قبل الحفظ.

5كيف يتعلّم

  1. الالتقاط. الخطافات في Claude Code تسجّل كل طلب وكل أداة لحظيًا. وعند كل START TIDOS يستورد TIDOS أيضًا سجلات Claude Code وOpenCode القديمة (تلقائيًا، وفقط الجديد منها).
  2. تقييم كل مهمة. يُحكم على النتيجة بالأدلة: هل شُغّلت فحوص (اختبارات، lint، بناء) وهل نجحت؟ هل صحّحت النموذج (بالعربية أو الإنجليزية أو الفرنسية)؟ هل حدثت أخطاء في الأدوات؟ النتيجة: نجاح، فشل، أو غير معروف.
  3. التصنيف. كل مهمة تُصنَّف حسب النوع (إصلاح خطأ، ميزة، نشر، إعادة هيكلة، سؤال…) والتقنية (Python، Flutter، Firebase…).
  4. التقطير إلى خطط عمل. من مهام النماذج القوية الناجحة يستخرج: أين يعيش الكود، أي ملفات تُقرأ أولًا، أي فحوص تُعاد، والفخاخ (فحص فشل ثم نجح، تصحيحاتك، محاولات فاشلة مفيدة).
  5. قواعدك أنت. الجمل التوجيهية التي تكرّرها (مرتين أو أكثر، بصياغة متقاربة) تصبح قواعد دائمة للمشروع، مثل «لا تغيّر سلوك التداول».
  6. ملاحظات النموذج القوي. بعد جلسات النماذج القوية، يكتب نموذج رخيص (بحد 0.05$) 1–3 نصائح عملية للنماذج الأضعف، ويمكن للنموذج القوي ترك نصيحة بنفسه بأمر note.
  7. الجودة والنسيان. لكل خطة عمل ثقة ورتبة (E–S). الثقة تقلّ مع قِدم الأدلة (بعد 30 يومًا، إلى النصف كحد أقصى)، والخطط التي توقفها أنت لا تُقدَّم أبدًا.
TIDOS لا يتعلّم من اختباراته الخاصة (الزنزانات)، حتى لا يتعلّم من نفسه.

6كيف يوجّه النماذج الضعيفة

الموجز عند البداية

عند START TIDOS بنموذج ضعيف يحصل على: قواعد العمل السبع، وحقائق المشروع (التقنيات، أوامر الفحص، ملاحظات النشر وgit)، وقواعدك الدائمة، وأفضل خطط العمل لهذا المشروع، والأدوات المثبّتة كفحوص إضافية (مثل ruff check . أو gitleaks detect).

قواعد النموذج الضعيف

  1. خطوة صغيرة واحدة في كل مرة.
  2. اقرأ قبل أن تعدّل.
  3. مسارات نسبية فقط.
  4. حدّد الفحوص أولًا (عرّف «الانتهاء» قبل البدء).
  5. شغّل الفحوص بعد كل تغيير.
  6. لا تقل «انتهيت» دون مخرجات الفحص، واطلب الإذن في الأفعال الخطيرة.
  7. بعد 3 أخطاء متطابقة: توقّف، اشرح، واقترح نموذجًا أقوى.

توجيه لكل طلب

مع كل طلب جديد، يصنّف TIDOS الطلب ويعيد (في أقل من 1.6KB) خطة العمل المطابقة فقط، مع خطوة «الفحوص أولًا» المناسبة لنوع المهمة: لإصلاح خطأ ← أعد إنتاجه بفحص يفشل؛ لميزة ← اكتب السلوك المتوقع كفحوص؛ للنشر ← موافقة صريحة على الأمر نفسه؛ لسؤال ← لا تعدّل الكود.

الفرض بالكود (في Claude Code)

الخطافما يفعله في وضع التوجيه
UserPromptSubmitيحقن التوجيه الخاص بالطلب تلقائيًا.
PreToolUseيمنع التعديل حتى يقرأ النموذج أو يبحث بعد طلبك.
PostToolUseيكتشف التعثر: ثالث فشل متطابق ← يوقف النموذج ويقترح نموذجًا أقوى.
Stopيمنع الإنهاء إذا تغيّر الكود ولم ينجح أي فحص بعد آخر تعديل (أو يجب أن يصرّح بأنه «غير مُتحقَّق منه»).

في الأدوات الأخرى (OpenCode، Gemini…) يصل التوجيه عبر مخرجات START TIDOS وخادم MCP (أداة tidos_guide).

7كيف يتطوّر (Solo Leveling)

مثل الأنمي، يرتفع مستوى TIDOS مع العمل الحقيقي، لكن فقط بالأدلة:

الحدث في مهمةXP
نجاح+20
نتيجة غير معروفة+5
فشل−10
آخر فحص نجح+5
أول فحص نجح (صحيح من أول مرة)+5
صحّحتَ النموذج−10

المستوى n يحتاج 100 × (n−1)^1.5 نقطة XP. وهناك مستوى عام، ومستوى لكل مشروع (مجال).

Sمستوى ≥ 50
A≥ 35
B≥ 20
C≥ 10
D≥ 5
E≥ 1

الخصائص الخمس

  • INT الذكاء: نسبة نجاح المهام ذات النتيجة الواضحة.
  • PRE الدقة: آخر تشغيل للاختبار أو الفحص أو البناء نجح.
  • DIS الانضباط: مهام عدّلت الكود وشغّلت تحققًا.
  • WIS الحكمة: إجابات لم تضطر إلى تصحيحها.
  • AGI الرشاقة: مهام انتهت دون خطأ في الأدوات.

ما الذي يُفتح مع الارتفاع؟

  • مسودات مهارات: خطة عمل نجحت 10 مرات أو أكثر برتبة B فما فوق ← مسودة SKILL.md في ~/.tidos/drafts/skills.
  • تغيير الوظيفة: مجال يصل إلى المستوى 15 ← مسودة وكيل متخصص لهذا المشروع، تتضمن قواعدك الدائمة.
  • جيش الظلال (تبويب «الجيش»): وكلاؤك الفرعيون (المعماري، المراجع، المختبِر، الأمني، الباحث، الواجهات، الموبايل) والوكلاء المدمجون في الأدوات. كل مهمة تكسب XP المهمة التي خدمتها (فحوص ناجحة، نجاح من أول مرة، ناقص تصحيحاتك)، فالرتبة تقيس الجودة لا الكثرة. لكل جندي ملف دروس خاص (~/.tidos/army/) يقرؤه قبل أن يبدأ.
  • ARISE: عندما يتكرر نوع عمل ناجح لا يغطيه أي جندي (مثل Firebase أو Python)، يكتب TIDOS مسودة جندي متخصص. اختبره على الزنزانات بالأمر tidos_evals run --agent claude:haiku --unit NAME، ثم فعّله بزر ARISE (يذهب إلى ~/.claude/agents، ويمكن التراجع). الجندي الذي يفشل كثيرًا يُقترح تحسينه أو تقاعده في طابور التطوّر.
  • المهام اليومية: أنجز 3 مهام مُتحقَّق منها، صفر تصحيحات، تحقّق من كل تعديل.
المسودات لا تُفعَّل تلقائيًا أبدًا. أنت تراجعها وتنقلها إلى .claude/skills أو .claude/agents إن أعجبتك.

8كيف يطوّر نفسه

  1. طابور التطوّر. النماذج (عبر tidos_propose) وأنت (عبر الأمر أو مركز التحكم) تضيفون اقتراحات لتحسين TIDOS، بأولويات.
  2. قرارك. في تبويب «التطوّر» تقبل أو ترفض كل اقتراح.
  3. التنفيذ الآلي الآمن. python scripts/self_improve.py ينفّذ اقتراحًا مقبولًا واحدًا في نسخة عمل مؤقتة على فرع auto/…، ويشغّل كل الفحوص (الاختبارات، مدقق المواصفات، تزامن الإضافة)، ولا يحفظ إلا إذا نجحت كلها. لا يرفع ولا يدمج أبدًا: أنت تراجع وتدمج.
  4. المهمة اليومية. python scripts/daily_quest.py: اختبارات، مواصفات، تزامن الإضافة، صلاحية الزنزانات، تحديث التعلّم، الحالة ← تقرير في ~/.tidos/reports. أي تراجع يظهر كإشعار.
  5. اختبار حذف القواعد. tidos_evals run --ablate N يشغّل وضع التوجيه دون القاعدة N ويقارن. إن لم يسُؤ الأداء، يُقترح حذف القاعدة: TIDOS يبقى خفيفًا.
  6. الزنزانات. 30 مهمة اختبار بفحوص مخفية (E إلى S) لقياس: هل يجعل TIDOS النماذج أفضل فعلًا؟

9كشّاف الأدوات

  • الحاجات: يكتشف ما ينقص كل مشروع حسب تقنياته (ماسح أسرار، ماسح ثغرات الاعتماديات، lint…).
  • الثقة (0–100): من النجوم، وحداثة التحديث، والرخصة، وOpenSSF Scorecard. المستودع المؤرشف = 0.
  • التثبيت بالموافقة: شغّل مفتاح tool_install ← وافق ← اضغط «ثبّت». فقط أدوات الكتالوج، بإصدار محدد أو بتنزيل رسمي تُطابَق بصمته SHA-256، داخل حسابك فقط ودون صلاحيات المدير، وتُرفض إن كانت الثقة أقل من 70.
  • الاندماج: الأداة المثبّتة تُضاف إلى توجيه النماذج الضعيفة كفحص إضافي، ويسمح tidos_verify بتشغيلها، ويُحسب لها XP من استخدامها الحقيقي.
  • الحظر: أداة لا تفيد؟ «احظر» فلا تُقترح بعد ذلك. و«أزل التثبيت» تزيل ما ثبّته TIDOS فقط.
  • خوادم MCP تبقى يدوية (أمر claude mcp add تشغّله أنت).

10مركز التحكم /TIDOSZIT

الدخول

  1. اكتب /TIDOSZIT في Claude Code (أو شغّل scripts\tidoszit.ps1). يفتح المتصفح على http://localhost:8767 (على جهازك فقط).
  2. تحقّق بحساب Google الخاص بالمالك (لا يُقبل غيره).
  3. اكتب كلمة مرور التحكم في المتصفح فقط. تُحفظ بصمتها فقط في Firestore. 5 محاولات خاطئة = قفل 15 دقيقة. الجلسة 30 دقيقة.
  4. زر العربية / English في الأعلى يبدّل اللغة.

شريط «اسأل TIDOS» والبحث

اسأل: سؤال بلغتك العادية (مثل «أي مشروع يفشل أكثر ولماذا؟»). يُبنى ملخص منقّى من آخر 30 يومًا ويُرسل لنموذج رخيص دون أي أدوات (بحد 0.05$)، ويجيب بالعربية إذا كانت الواجهة بالعربية. سؤالك لا يُسجَّل. بحث: كلمات في المهام وخطط العمل والذاكرة والتقييمات والاقتراحات، والنقر على نتيجة يفتح التبويب المناسب.

11الاستخدام اليومي

أ) مع Claude أو نموذج قوي

  1. افتح مشروعك في Claude Code واكتب START TIDOS. سيظهر «mode: learn».
  2. اعمل كالعادة. اطلب تشغيل الفحوص الحقيقية قبل إنهاء أي مهمة.
  3. إن أخطأ النموذج، صحّحه بوضوح. تصحيحاتك المتكررة تصبح قواعد دائمة.
  4. للمهام الكبيرة: /tidos وصف المهمة ← خطة (المعماري) ← تنفيذ ← تحقق (المختبِر) ← مراجعة ← ملاحظة تعلّم ← تقرير.

ب) مع نموذج مجاني أو ضعيف (مثل OpenCode)

  1. في مشروعك، اكتب START TIDOS. سيظهر «mode: guide» مع الموجز.
  2. اطلب مهمة واحدة واضحة في كل مرة. TIDOS يعطي النموذج الخطوة الأولى والفحوص.
  3. إن توقّف النموذج بعد 3 أخطاء متطابقة، انتقل لهذه الخطوة إلى نموذج قوي، ثم ارجع.
  4. لا تقبل «انتهيت» دون مخرجات فحص.

ج) أسبوعيًا

  • افتح /TIDOSZIT: اقرأ الإشعارات، اقبل أو ارفض الاقتراحات، راجع المسودات المفتوحة.
  • شغّل python scripts/daily_quest.py (أو جدوله يوميًا).
  • انسخ الدماغ احتياطيًا من تبويب الأمان.
  • أوقف خطط العمل الضارة أو القديمة من تبويب «خطط العمل».

12مرجع الأوامر

من داخل مجلد TIDOS (على Windows استعمل python -I كما هو مكتوب):

# البداية والحالة
START TIDOS                                     # في محادثة أي أداة
python -I tidos_learn/__main__.py status        # نافذة الحالة في الطرفية
/TIDOSZIT                                       # مركز التحكم (Claude Code)
.\scripts\tidoszit.ps1 -Stop                    # إيقاف مركز التحكم

# التعلّم
python -I tidos_learn/__main__.py distill       # تحديث التعلّم (استيراد + تقطير + XP)
python -I tidos_learn/__main__.py note --project NAME "نصيحة"
python -I tidos_learn/__main__.py proposals --add "عنوان"   # --accept/--reject ID
python -I tidos_learn/__main__.py dataset       # تصدير عملك المُتحقَّق منه (JSONL)

# التوجيه والمراجعة
python -I tidos_session/__main__.py guide "طلبك"            # التوجيه لطلب واحد
python -I tidos_session/__main__.py review --with claude:haiku   # رأي ثانٍ من نموذج آخر

# التطوّر والاختبار
python scripts/daily_quest.py
python scripts/self_improve.py
python -I tidos_evals/__main__.py run --agent opencode:opencode/big-pickle --tidos compare

# الأدوات
python -I tidos_scout/__main__.py needs --project PATH --trust
python -I tidos_scout/__main__.py install NAME --yes        # بعد الموافقة + مفتاح tool_install

# الدماغ
python -I tidos_brain/__main__.py backup        # --list للعرض
python -I tidos_brain/__main__.py restore NAME --yes
python -I tidos_brain/__main__.py install-hooks

13الأمان والخصوصية

  • كلمة مرور التحكم تُكتب في المتصفح فقط، وإن كتبتها في محادثة أو طرفية، غيّرها فورًا من تبويب الأمان.
  • مركز التحكم يعمل على 127.0.0.1 فقط، مع حماية من CSRF وإعادة ربط DNS وسياسة أمان محتوى صارمة.
  • المعرفة الخاصة لا تدخل المستودع العام؛ وبوابة المساهمات في CI ترفض أي مسودة خاصة أو أسرار.
  • التحديث لا يُثبَّت إلا بموافقتك، ولا يحذف ملفاتك أبدًا.
  • التطوير الذاتي يعمل على فروع منفصلة، ولا يرفع ولا يدمج.
  • لا يُعدِّل TIDOS إعدادات Claude Code أو ينشر إلى Firebase أو يرفع إلى GitHub من تلقاء نفسه، ولا يغيّر مفاتيح الإيقاف.

14نصائح لتسريع التعلّم

  • اجعل لكل مشروع أمر فحص واضحًا (اختبارات، lint، بناء)، فهو مصدر الأدلة الأهم.
  • اكتب طلبات واضحة تبدأ بفعل («أصلح»، «أضف»، «راجع»)، فيُحسِن TIDOS تصنيفها.
  • صحّح بجمل محددة وكرّرها عند الحاجة، فتتحوّل إلى قواعد دائمة.
  • استخدم النماذج القوية للمهام الجديدة والصعبة، والضعيفة للمهام المتكررة التي لها خطط عمل.
  • كل خطأ حقيقي يُصلح يمكن تحويله إلى زنزانة جديدة: tidos_evals new --suite S --name N --source PATH.
  • راجع المسودات وفعّل الجيد منها: هكذا تكبر مهارات TIDOS بشكل دائم.
