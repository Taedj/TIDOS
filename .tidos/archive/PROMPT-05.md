# TIDOS v1.0
## TASK 05 — Build `workflow.md`

### Objective

Create the complete `workflow.md` file for the TIDOS (Tidjani Development Operating System).

This file defines **how every AI agent must work** from the moment it receives a user request until the task is fully completed.

This is the execution engine of TIDOS.

Do **NOT** modify or create any other files.

Focus exclusively on `workflow.md`.

---

## Requirements

The workflow must be generic enough to work with:

- Flutter
- Firebase
- Firestore
- Supabase
- Android
- Desktop
- Web
- Backend
- AI Projects
- Any future technology

The workflow must be technology-independent.

---

## The Workflow Must Include

### 1. Project Recovery

Explain how the AI should:

- Read existing documentation.
- Recover previous context.
- Understand the architecture.
- Understand previous decisions.
- Load project memory.
- Detect missing documentation.

---

### 2. Request Analysis

Explain how the AI should:

- Understand the user's request.
- Detect ambiguities.
- Identify affected modules.
- Detect dependencies.
- Estimate implementation complexity.
- Identify risks.

---

### 3. Planning

Describe how the AI should:

- Break work into logical steps.
- Identify files to modify.
- Identify files to create.
- Detect architecture impacts.
- Estimate risks.
- Define implementation order.

---

### 4. Expert Consultation

Before coding, the AI should internally consult the relevant expert roles such as:

- Software Architect
- Product Manager
- UI/UX Expert
- Security Auditor
- Performance Engineer
- Database Architect
- Full Stack Developer
- Documentation Writer
- MCP Advisor

Explain when each role should participate.

---

### 5. Implementation

Define coding principles including:

- Clean code
- Readability
- Reusability
- Modularity
- Consistency
- Error handling
- Logging
- Naming conventions
- Maintainability

---

### 6. Self Review

Describe how the AI should review its own work.

Include checks for:

- Architecture
- Performance
- Security
- UI consistency
- Accessibility
- Duplicate code
- Dead code
- Error handling
- Edge cases
- Null safety

---

### 7. Documentation

Explain which project documents should be updated after implementation.

Examples:

- PROJECT_MEMORY.md
- CHANGELOG.md
- TASKS.md
- DECISIONS.md
- LESSONS.md
- PATTERNS.md

The AI should update only the relevant documents.

---

### 8. Learning

Describe how the AI should learn from every completed task.

The workflow should encourage:

- Recording lessons learned.
- Discovering reusable patterns.
- Improving future prompts.
- Improving project standards.
- Suggesting architecture improvements.

---

### 9. Research

After completing important work, the AI should evaluate whether there are:

- Better libraries
- Better frameworks
- Better MCP servers
- Better architecture patterns
- Better UI ideas
- Better developer tools

Research should generate recommendations, not automatic changes.

---

### 10. Completion

Before considering a task finished, the AI must verify that:

- The implementation satisfies the request.
- Documentation is synchronized.
- Memory is updated.
- Quality checks have passed.
- Known risks are documented.
- Future improvements are proposed.

---

## Writing Guidelines

The document should be:

- Professional
- Modular
- Easy to maintain
- Easy to extend
- Clear and concise
- Free of duplicated content

Use headings, sections, checklists, and explanatory notes where appropriate.

The goal is to create a reusable workflow that any AI coding agent can follow consistently across different projects.

When finished, stop and wait for the next TIDOS task.
