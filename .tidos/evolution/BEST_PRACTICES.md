# TIDOS Best Practices Registry

This file maintains an evolving collection of engineering best practices validated by real project experience. Only practices that have been empirically proven in production-grade development are recorded here.

---

## Inclusion Criteria

A best practice is added only when:
1. It has been applied successfully in at least one real project context.
2. Its benefits are empirically observable (faster builds, fewer bugs, cleaner code).
3. Its trade-offs are honestly documented.

---

## Entry Format

```markdown
### BP-[NNN]: [Practice Title]

- **Domain**: [Architecture | Security | Performance | Testing | UI/UX | Database | DevOps | Documentation]
- **Validated In**: [Project or technology context where this was proven]

#### Description
[Clear explanation of the practice and when to apply it.]

#### Benefits
- [Concrete benefit 1]
- [Concrete benefit 2]

#### Trade-offs
- [Honest trade-off or cost of applying this practice]

#### Recommended Usage
[Specific guidance on when this practice should and should not be applied.]
```
