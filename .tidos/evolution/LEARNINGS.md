# TIDOS Learnings Registry

This file captures lessons learned, mistakes, successes, and prevention rules extracted from real development work. Entries are appended after every significant feature completion during Stage 8 (Learning) of the TIDOS Workflow.

---

## Observation Protocol

During development, TIDOS silently observes:
- Architecture choices and folder organization decisions
- Naming conventions and coding style patterns
- Error handling strategies and state management approaches
- Database design (Firestore, Supabase, PostgreSQL, SQLite)
- Flutter/Desktop/Android/Web platform-specific patterns
- Reusable widgets, services, and component structures
- Testing, deployment, documentation, and review workflows

Observations are **never intrusive**. They are distilled into entries only after task completion.

---

## Entry Format

```markdown
### LEARNING-[NNN]: [Short Descriptive Title]

- **Date**: [YYYY-MM-DD]
- **Category**: [Mistake | Success | Discovery | Optimization]
- **Context**: [What was being implemented and what happened]
- **Root Cause / Key Insight**: [Why it happened or why it worked]
- **Resolution / Outcome**: [How it was resolved or what was achieved]
- **Prevention Rule / Reuse Guideline**: [Actionable rule for future tasks]
- **Reusable Pattern Candidate**: [Yes / No — If yes, promote to PATTERNS.md]
- **Possible Automation**: [Any workflow step that could be automated]
```
